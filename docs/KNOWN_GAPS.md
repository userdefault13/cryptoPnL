# Known gaps (P2, PR #3)

These are limits of the current ingest and classifier that we know about. Each one is either sent to `review_queue` or flagged in
the ledger. None of them is silently turned into a wrong category or a made-up number. Test wallet: `<TEST_WALLET>`.

| # | Gap | Effect today | Mitigation / when it closes |
|---|-----|--------------|-----------------------------|
| 1 | **Baazaar buy-order events are not ingested** (ERC1155BuyOrderAdd / ERC721BuyOrderAdd / cancel events). HyperSync market logs are filtered to events where the wallet is a topic. The Add events are emitted by the diamond, and the order id is not in the wallet's own logs at placement time. | A placement is recognised only by the wallet's own tx: tx.to is the Baazaar diamond and the selector is `0x4cc4a386`. The order id is stamped on the placement rows when the fill or cancel reveals it. Fill matching (B2) works like this: if an escrow entry is already linked to the order id, use it. Otherwise use exactly one unlinked open entry with amount = price×qty. Otherwise (first partial fill) use exactly one unlinked entry that is a multiple of price and larger than the payment. Anything else goes to review. | Ingest the BuyOrderAdd events (topic: buyer) in a later phase. Then match placement to order id directly. |
| 2 | **EIP-7702 / batched placement miss.** A buy order placed through a delegated (EIP-7702) or batched call has a different top-level `to`/selector than `0x4cc4a386`. | It is not recognised as escrow_out. Under B1, any token to or from the Baazaar/GBM diamond that no escrow or market rule claims goes to **review**, never withdrawal or deposit. | Decode the inner calls (P4 trace work) or use gap #1. |
| 3 | **ERC721 buy-order fills** (`ERC721BuyOrderExecuted`). The event layout has not been checked against a real tx in this wallet's history. | Review (`erc721 buy-order fill: event layout not verified`). | Check the layout on an explorer before enabling it. |
| 4 | **GBM refunds without an indexed event** (e.g. 0x9248c7…). | Matched by rule: the refund must be ≥ the escrowed bid and ≤ 1.10× it (observed incentives are 0.5% and 5%), and exactly one open escrow must fit. Otherwise review. The incentive part is recorded as `income`. | Ingest GBM refund/outbid events where the wallet is not a topic. |
| 5 | **Internal ETH** (value moved by contract calls; no log, not a tx `value`). | Not in the ledger. A DEX-router tx with only fungible-out legs goes to review (`native leg not indexed (internal ETH gap)`). | Trace API (`trace_*` / `debug_traceTransaction`) in P4. Not available on the free RPC tier used now. |
| 6 | **CCTP emitter is not verified.** bridge_in requires tx.to to be a Circle CCTP MessageTransmitter on Base (only V1 `0xAD09780d193884d503182aD4588450C416D6F9D4` and V2 `0x81D40F21F12A8F0E3252Bccb954D722d4c464B64`; TokenMessengers dropped. | 8 | **Untracked legs.** Non-allowlisted token legs in wallet-sent txs (e.g. the LINK leg of 0x16d862…). | `untracked`, `pnl_excluded`, no lot.
