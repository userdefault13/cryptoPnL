# Known gaps (P2, PR #3)

These are limits of the current ingest and classifier that we know about. Each one is either sent to `review_queue` or flagged in
the ledger. None of them is silently turned into a wrong category or a made-up number. Test wallet: `<TEST_WALLET>`.

| 1 | **Baazaar buy-order events are not ingested** (ERC1155BuyOrderAdd / ERC721BuyOrderAdd / cancel events). HyperSync market logs are filtered to events where the wallet is a topic. The Add events are emitted by the diamond, and the order id is not in the wallet's own logs at placement time. | A placement is recognised only by the wallet's own tx: tx.to is the Baazaar diamond and the selector is `0x4cc4a386`. The order id is stamped on the placement rows when the fill or cancel reveals it. Fill matching (B2) works like this: if an escrow entry is already linked to the order id, use it. Otherwise use exactly one unlinked open entry with amount = price×qty. Otherwise (first partial fill) use exactly one unlinked entry that is a multiple of price and larger than the payment.
